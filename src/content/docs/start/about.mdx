## 为什么自研媒体网关

Emby 拥有覆盖几乎所有平台的客户端，这是 Lumen 兼容 Emby 协议的原因。但 Emby Server 是为家庭和小规模片库设计的。当片库达到数十万个文件、许多人同时使用时，我们在实际运行中反复遇到这些问题：

- **内存占用大**：同等规模的片库，Emby Server 常驻内存约 19 GB，内存打满后会被系统强制重启，正在观看的人随之中断。
- **搜索偶尔极慢**：多数搜索很快，但最慢的 1% 要等 20 秒以上，期间服务器的其他请求也会变慢。
- **新片入库慢**：依赖定期扫描，片库越大，一轮扫描越久。
- **后台任务与播放争抢资源**：扫描、刮削繁忙时，正在进行的播放也会受影响。
- **账号各自为政**：Emby 账号需要单独管理，无法与订阅、线路、设备统一。

于是我们从零编写了 Lumen 媒体网关：一个兼容 Emby 协议的媒体服务端。现在，Lumen 的账号认证、播放、片库与检索全部由它承担，您不需要更换已经习惯的客户端。

## 媒体网关带来了什么

### 播放

- **拖动即播**：99% 的拖动请求在 25 毫秒内开始返回数据，拖到哪里就从哪里播。
- **开播预热**：打开影片时提前准备好文件的开头和结尾，高码率原盘也能很快开播。
- **续播定位**：记住每个文件的索引，再次继续观看时几乎立即从上次的位置开始。
- **下一集预热**：看剧时提前准备下一集，切集不用等待。
- **播放优先**：片库扫描、资料补全等后台任务一律为播放让路。

### 片库与检索

- **自动入库**：新片最快约半分钟出现在片库中，多数在两分钟内。
- **多版本合并**：同一部影片的 4K、1080p 等版本合并为一个条目，在客户端中直接切换。
- **自定义媒体库**：按类型、人物或豆瓣、TMDB 等榜单建立的媒体库，像普通媒体库一样出现在所有客户端中。
- **中文检索**：片名任意片段、原名、简繁互通、拼音首字母都能搜到，例如输入 `hbld` 即可找到《黑帮领地》。

### 账号

- 控制台与所有客户端共用一个账号；修改密码或移除设备后，相应的设备立即登出。
- 每台登录过的设备都列在账号设置中，可以随时查看和移除。

## 团队

Lumen 由一支技术人员与影视爱好者组成的团队开发和运营，成员在媒体库维护、网络优化与产品研发领域都有多年经验。我们以做产品的标准运营 Lumen：统一的界面语言、清晰的使用路径、稳定的运行，以及可以预期的长期维护。
